# 临时目录空间故障后的权重恢复

适用情况：旧训练在数据加载子进程创建`/tmp/pymp-*`时遇到ENOSPC，保留了可读取的G_A、G_B、D_A、D_B网络检查点。以下是权重与更新计数恢复：旧版本没有保存Adam、replay pool或RNG状态，因此无法逐步精确复现未中断的训练。

2026-10-21服务器检查结果：四份latest均可读取，浮点张量有限，G_A的`color_loss_updates=10000`。当前清单每轮5531次更新，保存点位于第2轮第4469次更新；目标80轮共442480次更新，剩余432480次。数字由清单与检查点计算，代码没有固定FLIR样本数。

## 1. 停止这次实验的旧进程

在Ubuntu执行。匹配限定为这次实验的启动器、训练主进程与持有同一命令行的数据加载子进程，不按Python进程名全局终止。

```bash
training_pattern='([r]un_learned_color[.]py|[t]rain[.]py).*--name[ =]rgb_prior_scratch80_loss001_seed42_v1([[:space:]]|$)'
pkill -TERM -f "$training_pattern"
pgrep -af "$training_pattern"
```

最后一条无输出才表示这次实验的可见旧进程已结束；仍有输出时先处理旧进程，不启动另一份训练。启动器也会检查可见Linux进程并拒绝并行恢复。

## 2. 上传并安装源码更新

将`learned_color_recovery_ubuntu_20261021.tar.gz`与对应`.sha256`文件上传到项目根目录。

```bash
cd /home/ubuntu/work/JiuZzi/Thermal_on_Mac
conda activate /home/ubuntu/work/JiuZzi/conda_envs/c1_sem512
sha256sum -c learned_color_recovery_ubuntu_20261021.tar.gz.sha256 &&
tar -xzf learned_color_recovery_ubuntu_20261021.tar.gz -C .
python scripts/package_learned_color_ubuntu.py --verify-installed
```

此包只有源码、配置、文档与校验清单。已有数据划分、RGB语义缓存、颜色先验、两个语义模型与这次10000步的GAN权重继续使用。

## 3. 只读预检

```bash
python -u scripts/run_learned_color.py --check-only --resume \
  --data-manifest runs/learned_color/data_seed42_v1/cycle_manifest.json \
  --prior runs/learned_color/rgb_prior_seed42_loss_v1.json \
  --semantic-checkpoint runs/pretrained/segformer_fmb_b3/best_model.pth \
  --name rgb_prior_scratch80_loss001_seed42_v1 --mode learned --gate-semantic \
  --epochs 80 --decay-epochs 40 --lr 0.0002 --save-every 5 --seed 42 \
  --color-loss-weight 0.01 --color-loss-warmup-steps 1000 --workers 0
```

应显示`saved_updates=10000`、`epoch_count=2`、`skip_positions=4469`、`remaining_updates=432480`。它验证四份文件可读取、张量有限、计数存在，以及学习率／原40+40预算／seed／颜色损失／可靠性配置与`train_opt.txt`一致；模型启动时还会严格检查实际权重结构和条件签名。只读检查不会备份、修改训练目录或运行GPU前向。

## 4. 接续训练

```bash
mkdir -p runs/training runs/tmp
export TMPDIR=/home/ubuntu/work/JiuZzi/Thermal_on_Mac/runs/tmp

nohup python -u scripts/run_learned_color.py --train --resume \
  --data-manifest runs/learned_color/data_seed42_v1/cycle_manifest.json \
  --prior runs/learned_color/rgb_prior_seed42_loss_v1.json \
  --semantic-checkpoint runs/pretrained/segformer_fmb_b3/best_model.pth \
  --name rgb_prior_scratch80_loss001_seed42_v1 --mode learned --gate-semantic \
  --epochs 80 --decay-epochs 40 --lr 0.0002 --save-every 5 --seed 42 \
  --color-loss-weight 0.01 --color-loss-warmup-steps 1000 --workers 0 \
  >> runs/training/rgb_prior_scratch80_loss001_seed42_v1_resume1.log 2>&1 &
```

```bash
tail -f runs/training/rgb_prior_scratch80_loss001_seed42_v1_resume1.log
```

本次只启动一次。恢复日志使用追加模式，旧启动日志保留在原路径。启动器创建唯一备份目录`runs/recovery/<name>/updates_10000_*/`，复制四份权重及原`train_opt.txt`、`color_train.json`并记录SHA256、恢复计数、缺失状态。后续更新仍写入原实验目录。

训练子进程的TMPDIR会强制指向`runs/tmp/<name>/`，位于项目数据盘；`workers=0`使用主进程加载数据，不再通过DataLoader子进程的资源共享队列传递张量。它不能保证其他GPU、磁盘或模型错误不会发生，也不改变已存在进程的环境。

恢复会先读取并跳过新数据迭代器中的4469个位置，每1000个位置输出进度，期间不做梯度更新。随后打印`next optimizer update is 10001`；第一次常规loss预计显示`epoch: 2, iters: 4500`。第2轮剩余1062次更新结束后继续第3轮，保持原40+40学习率日程，后续latest按原累计更新计数保存。

这里保留的是更新次数和轮次日程；原采样器、裁剪／翻转／dropout的随机状态与Adam动量均未保存，恢复后的样本顺序和参数轨迹会变化。论文或实验记录应注明这次权重恢复。不得把它描述为完整断点或逐步一致复现。

## 5. 完成与导出

完成时仍应看到`End of epoch 80 / 80`，原实验目录生成`80_net_G_A.pth`等文件，G_A保存计数应为442480。验证集选择检查点、测试导出与[原完整流程](从零训练学得颜色先验Ubuntu完整流程.md)相同。回传结果时同时带上原日志、恢复日志与`runs/recovery/<name>/updates_10000_*/recovery.json`，无需上传整个备份权重。

## 磁盘占用的证据范围

用户此前`df`显示根分区overlay占用430GB、数据盘剩54GB，而`du -xhd1 /`仅统计到当前用户可读取的约17GB；该命令隐藏了权限错误，容器文件系统与宿主存储的可见范围也不同。因此尚未确认根分区真实占用来源，需要管理员检查宿主存储、不可见目录及已删除仍被持有文件等。项目旧权重清理仅影响数据盘，不等于解决了共享根分区占用。
