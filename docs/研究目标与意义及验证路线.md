## 2. 最终希望解决的实际问题

面向夜间仅有热红外输入的人车场景，研究结构可信、语义一致、颜色合理的可见光表观生成。利用软轮廓、任务重要性、受约束补边与结构可靠性调节，减少重要目标的结构丢失、边界偏移、错误补线、区域错译和颜色串扰；进一步验证生成表征是否为人车感知带来额外收益。

可用于介绍项目的表述：

> 本研究面向夜间单热红外输入的人车感知场景，研究结构与语义约束的条件扩散生成。在保持行人、车辆位置和边界的前提下，改善颜色合理性与区域一致性，并通过与直接红外感知、相同条件辅助感知的对照，检验生成表征对人车检测的增量价值及其跨场景稳定性。

这是研究目标，不预设实验一定成功。生成图使用训练中学到的先验，不是新增的真实传感器观测；不能声称仅凭热红外恢复真实服装、车身颜色或不可见的细节。

## 3. 两项核心结论，需要分别证明

### 3.1 方法贡献：着色更合理，结构更忠实

希望提出的模块能够共同改善生成质量：

1. 颜色在语义区域内更合理、跨区域串色更少，表观自然度改善。
2. 行人、车辆等关键结构更完整，边界位置和形状与输入场景一致。
3. 对有局部证据支持的轮廓缺口提出补全候选，同时限制错误连接与伪结构的影响。
4. 利用结构可靠性调整对候选的依赖，而非强制把所有目标闭合或把所有补边全部使用。

“各指标都高”不是要求。应在关键指标上稳定优于合理基线，并报告颜色、结构、误补、速度等方面的取舍；例如FID/KID是越低越好，不能把所有指标都理解为数值越高越好。

至少比较：不补边、补边全部使用、相同补边候选加可靠性调节。必要时加入简单梯度强度筛选、恒定或打乱评分等对照，判断收益是否来自可靠性机制。评价补全正确性须使用独立标注或复核，不能把自己生成的轮廓当作真值，也不能仅凭更亮、更密、连通域更少宣称更准确。

固定生成骨干、预训练权重、数据、共同条件、训练预算与采样设置，在同一diffusion骨干内进行消融。仅仅更换骨干、使用SAM或增加模块数量，不单独构成贡献证明。

### 3.2 应用收益：生成表征确实帮助人车检测

希望在只输入热红外的条件下，利用可见光先验形成更易被感知模型使用的表征，降低行人、车辆等目标的漏检，同时控制误检和运行成本。

准确表述是“生成表征帮助检测器”，不能把彩色化生成器本身直接称为检测器。生成图更自然、生成指标改善，均不能替代下游检测证据。

下游检测验证使用人工检测标注。生成器的原训练设定与下游有监督检测训练应分别记录，不把整个系统笼统称为无监督。

## 4. 模块职责：重要性与可靠性分开

| 量或模块 | 回答的问题 | 最终希望发挥的作用 |
|---|---|---|
| 软轮廓E | 哪里存在边界线索？ | 提供连续的结构条件，保留细小、弱边线索 |
| 重要性／显著性R | 哪些结构对当前任务更重要？ | 优先保留人车等关键结构，限制非关键密集纹理的贡献 |
| 受约束补边 | 局部证据是否支持一个缺段候选？ | 提出有来源、可拒绝的补全候选，记录新增位置 |
| 结构可靠性C | 原始或补全轮廓可信多少、应该依赖多少？ | 降低错误或证据不足候选的干扰，允许保留不确定性 |
| 语义P与颜色先验K | 区域是什么、哪些外观合理？ | 约束类别关系和区域着色，减少错译与串色 |

真实清晰的叶片内部纹理可以可信却不重要；弱脚部边界可以重要却不确定。因此，R主要负责重要性取舍，C主要负责可信程度与结构依赖，两者不能合并为一个“删除纹理”分数。

旧实现中的语义可靠度Q不是结构C。未经独立校准验证，C宜称可靠性评分或依赖权重，不直接称为正确概率。低C也不自动等同于背景；应保留原始热红外内容路径。

## 5. 三组检测对照的可执行定义

以下是拟实施的验证设计，尚未确认服务器代码已实现这些检测接口。

共同条件指生成器已经使用、可由输入获得的语义以及轮廓、显著性等条件。B和C使用完全相同的条件，避免把这些条件的收益全部归于生成。具体集合在代码核对后固定。

| 组别 | 检测器可获得的信息 | 要回答的问题 |
|---|---|---|
| A：直接红外检测 | 原始红外T | 为什么不直接进行红外检测？ |
| B：共同条件辅助检测 | T＋共同语义／结构条件 | 收益是否已能由这些条件解释？ |
| C：生成辅助检测 | T＋与B相同的条件＋生成图或生成特征 | 在已有条件之上，生成模块是否还有额外价值？ |

第三组必须保留第二组条件。单纯比较“T＋语义”与“T＋生成图”，不宜直接当作严格的单因素生成模块消融。

具体实施：

1. 复用已经训练的生成器；先冻结生成器与条件模型，分别对训练、验证、测试图片推理并缓存，避免为三组各重训一次diffusion。
2. 选择同一种检测骨干和检测头，增加条件编码分支及生成表征分支，在对应组中关闭不使用的分支。分支结构、容量和实际计算量需要记录，必要时增加同等规模的额外红外特征分支作为容量对照。
3. A/B/C分别训练或微调检测器，使用相同人工检测框、类别、划分、骨干初始化、分辨率、增强与训练预算，并检查多个随机种子。几何增强须同步作用于图像、条件、生成结果和标注。
4. 保持生成图与原始红外的坐标对应；生成器若删除或移动目标，应计入系统错误，不能重新改框去迁就生成结果。测试真值框、真值掩膜不作为语义提示或生成输入。
5. 按视频或场景隔离训练、验证和测试；在验证集选择参数，使用未参与调参的数据检验最终结论。固定并记录扩散采样步数、引导设置、随机种子及额外预训练数据。

收益解释：B−A体现共同条件的贡献，C−B体现生成表征在这些条件之上的增量作用，C−A体现整个方案相对直接红外检测的作用。若C不能稳定超过B，不能声称已证明生成模块的检测价值。

检测评价至少报告整体和逐类AP、mAP、小目标／远处行人表现、固定误报水平下的召回率。记录波动与失败场景，不只展示少数成功图片。报告包含条件提取和扩散采样的端到端时间、显存与参数量；离线缓存后的检测耗时不能冒充在线系统总耗时。

## 6. 其他有说服力的价值与对应证据

| 价值角度 | 需要证明什么 | 证据方式与优先级 |
|---|---|---|
| 减少生成失真与虚构内容 | 不随意删除／增加人车、移动目标或生成伪结构 | 目标新增／消失、边界偏移与错误补边复核；属于方法贡献的深化，不重复计为独立创新 |
| 跨场景稳定性 | 不依赖某个视频或为FLIR特设的规则 | 未调参的视频、场景与外部数据评价；与生成质量、检测增益共同列为核心证据 |
| 辅助人工判读 | 人更准确、更快地发现人车和理解场景关系 | 盲测比较灰度红外、简单伪彩、红外＋语义叠加、生成图的任务准确率和耗时；作为可选扩展 |
| 降低标注需求 | 少量热红外标注下可维持感知性能 | 固定预训练知识与数据来源，在不同标注预算下比较性能曲线；作为可选扩展 |

人工判读任务应围绕人车发现、位置和场景关系，不让观察者把生成的衣服或车身颜色当作真实身份依据。跨数据集测试如有适配或微调，须报告其数据、标注和计算预算，区分直接泛化与适配后的效果。

## 7. 当前优先级与完成条件

优先做扎实三条：生成质量、生成表征的检测增益、跨场景稳定性。人工判读和少标注收益留作可选扩展，不要求为了“显得有意义”同时开展所有任务。

- [ ] 核对服务器实际运行的commit、配置、检查点与验证结果，完成固定D环境的完整模型检查。
- [ ] 在相同骨干和预算内验证着色、结构、补边与可靠性各自的作用。
- [ ] 完成独立的补边正确性与错误影响评价。
- [ ] 实施A/B/C检测对照，确认生成相对共同条件的额外收益及代价。

判定原则：只根据实际证据主张贡献。如果仅生成质量改善，就报告生成方法的收益；若检测和跨场景对照也成立，再增加相应应用与泛化结论。不能用轮廓预览、运行检查或论文先例替代本方法的实验结果。
