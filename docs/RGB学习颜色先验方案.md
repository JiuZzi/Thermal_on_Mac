# 从 RGB 学习颜色先验：待实施方案

日期：2026-10-20。用户希望颜色先验从真实 RGB 学习，并明确要求考虑过拟合与学习质量。本文件是设计建议和数据核查记录；尚未拟合先验、下载新模型或修改当前服务器上的两组实验。

第一步进度：已完成[32图RGB语义审查与稀疏种子准备](RGB语义区域审查.md)。复用现有模型导出两种输入的对照，经视觉复核保留67块内部种子；不代表全量RGB语义标签已经可靠。颜色分布拟合与验证尚未开始。

## 当前已有的学习与拟新增的学习

现有生成器已经通过真实 RGB 的对抗目标学习可见光外观；这属于隐式学习。当前人工颜色版额外使用手工色样和容差，不能称为已经从 RGB 学得的显式颜色先验。

建议新增的是类别条件颜色分布 `p(a,b | c)`：从训练 RGB 的语义区域中拟合 Lab 色度的多峰分布。第一版采用每类小型高斯混合模型（GMM），将颜色中心、范围与出现频率都交给数据估计；不把整类压缩成一个平均色。先验拟合后冻结，生成器继续训练。

这是统计学习的基线，并非另训练一个大型颜色网络。类别分布本身仍然粗糙，不能自动区分树干与树叶、判断同类车辆的真实车身颜色或充分表达天气风格；如后续证据支持，再考虑类别＋上下文的条件分布。

## 数据核查

依据本地 `FLIR_protocol_v2/manifest.csv` 与 `protocol.json`：

| 划分 | 图像数 | 不同 video_id 数 |
|---|---:|---:|
| trainA（日间RGB） | 6191 | 115 |
| trainB（夜间TIR） | 2110 | 24 |
| testA（日间RGB） | 696 | 13 |
| testB（夜间TIR） | 112 | 4 |

A、B 各自的训练／测试视频交集均为0。testB中102张来自同一视频，因此112张不能按112个独立场景解释。

现有 FLIR 协议明确注明：检测框不等于完整语义掩膜。现有 FMB 生产推理入口使用灰度复制为三通道。后续32图审查中，RGB探针略好但仍有高分误分，不能直接把其RGB／可见光灰度预测当成全量正确标签。

## 建议的信息流

```text
训练 RGB → 可靠语义区域 → Lab色度采样 → 拟合每类多峰颜色分布 → 冻结保存
                                                               ↓
当前 TIR → 冻结语义 P ───────────────────────────────────────→ 颜色分布条件
当前 TIR、joint512、P、颜色条件 → 条件生成器 → RGB
```

RGB只在先验学习及原有GAN训练阶段使用；部署时不要求一张对应RGB，不新增TIR/RGB配对假设。原始TIR通路、joint512和预留C的第三通道继续保留。

## 实施顺序

1. **先确定RGB区域来源。** 在按视频和场景选出的少量训练RGB上审阅现有分割模型的适用性。若不可靠，需要适配RGB的冻结分割器或少量人工区域标注；新增外部模型／标签的来源与监督假设应在实施前明确。少量人工审查本身不代表全数据分割准确。
2. **建立独立的先验学习划分。** 从trainA按video_id留出验证视频，所有同视频帧处于同一侧；保存划分清单和种子。testA/testB不用于拟合先验或选择混合数、容差和损失权重。
3. **控制重复与伪标签污染。** 每视频／图像／类别设采样上限，避免长视频和大面积天空道路主导统计；审查类别混淆、边界混色和曝光异常。对覆盖不足的类保留缺乏可靠先验的状态，不能强造一个窄颜色范围。
4. **拟合小型多峰分布。** 在预先限定的小候选集合中选择GMM复杂度，加入协方差正则，依据留出视频的拟合质量及稳定性选择。不能只看训练似然，也不通过强色相扰动人为制造所谓真实颜色多样性。
5. **先验证先验，再接入生成。** 将可靠先验冻结，记录数据／类别映射／参数哈希。保留多个颜色模式的信息，调整现有分支编码；当前6通道只含矩信息，直接换成一个学得均值会丢失多峰信息。
6. **分开检验条件与损失。** 先比较仅语义与语义＋数据先验条件；如需颜色约束，再加一组相同条件、低权重约束。不能单凭逐像素负对数似然变小宣称着色提升：它可能促使所有同类像素趋向最高密度颜色。也不能强制每个单独区域都呈现整类训练集的所有颜色比例。

拟合后的先验不从生成RGB回填更新，避免把生成错误重新当成颜色知识。学习出的RGB先验也不能纠正所有TIR语义错误；高分错分仍可能引导错色。

## 过拟合与泛化的证据边界

- **先验本身：** 比较训练与未参与拟合的视频上、逐类别的真实RGB负对数似然和颜色覆盖；记录支持视频／区域数，按视频统计波动。训练好而留出差，或更换拟合视频后颜色模式大幅改变，是需要检查的信号。
- **生成器：** 独立检查TIR着色在未见场景上的错色、串色、单一套色、结构损伤和伪纹理。先验在RGB上拟合良好，不等于它能改善TIR生成。
- **旧权重的限制：** 现有第80轮生成器已见过原始trainA；之后从trainA切出的先验验证视频，仅对新拟合的先验是留出，不能宣称对整个生成器未见。需要整系统严格留出时，应统一重新训练或使用完全未见的数据。
- **测试集的限制：** 既有112张已多次用于开发观察。后续可继续作固定开发对照，若据此反复选方案，正式泛化还需另保留未参与选择的测试数据。
- **低容量并非保证：** 小GMM也会受有限场景、伪标签和频率偏差影响；未来若采用神经先验，还需额外控制网络容量、正则化和早停。

## 如何判断是否学得好

| 检查层级 | 看什么 | 不能据此直接宣称什么 |
|---|---|---|
| RGB语义区域 | 天空／植被等的人工核查、错误来源、独立区域标注 | 模型分数高不代表标签正确 |
| 先验拟合 | 留出视频上逐类似然、合理颜色覆盖、模式／参数稳定性 | 训练损失低不代表泛化，分布越窄或越宽都不天然更好 |
| TIR生成质量 | 同样本类别错色、串色、自然度、结构保持及伪纹理 | 更鲜艳或更接近类均值不代表正确 |
| 分布与结构指标 | 同协议KID/FID作为辅助，结合独立局部审查与结构评价 | 单个分布指标或轮廓代理不能证明全部质量 |

无配对testA/testB不能直接计算逐图PSNR/SSIM/LPIPS来证明恢复了真实颜色。同一个伪标签模型在生成图上再次判定一致，也不能独自作为正确性证据。

最小生成对照：仅语义、人工颜色先验、RGB学习颜色先验，使用同初始化、种子、数据预算与骨干。需要排除额外训练影响时加入同预算none组。若数据版同时改变输入编码和损失，应将结论限定为组合效果。

## 参考依据与本方案的关系

- [Colorful Image Colorization, ECCV 2016](https://richzhang.github.io/colorization/)：将灰度着色建模为颜色分类以表达不确定性，并讨论颜色多样性与数据集偏差。它不是TIR专用方案；本方案借鉴分布建模思想，不把可见光灰度等同于TIR。
- [Gaussian Mixture Model Selection, scikit-learn官方文档](https://scikit-learn.org/stable/auto_examples/mixture/plot_gmm_selection.html)：GMM组件数、协方差类型与模型选择示例；本文提出的类别条件与按视频留出设计属于本项目建议。
- [MUNIT, ECCV 2018](https://arxiv.org/abs/1804.04732)：无配对转换中通过内容／风格表示建模多种可能输出，可作未来上下文／风格先验参考，当前未引入此架构。
