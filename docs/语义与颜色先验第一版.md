# 语义与颜色先验第一版

日期：2026-10-20。当前阶段与后续 R/C/补边路线见[项目进度](项目进度.md)。

## 目标和实际范围

旧版只把 15 类响应压缩为轮廓重要性，实际输入是 `[TIR,joint512,0]`。本版增加独立 `semantic_color_cycle_gan` 入口：

```text
TIR ───────────────────────────────────────────┐
TIR → 冻结 SegFormer512 → P(15类) → 原 joint512 ─┤→ 原 ResNet 彩色化骨干 → RGB
                         ├→ 完整 P ─────────────┤  在5个特征尺度加入独立条件分支
                         └→ 宽松颜色范围 K ─────┘
RGB + P/K → 区域色度范围软约束
```

原始输入仍为 `[TIR,joint512,0]`，第三通道保留给将来的边缘置信度。没有新补边，没有训练或微调语义网络，没有新增外部预训练模型，也未接入 JR、对比学习或 diffusion。

新增分支使用零初始化投影：从旧版 G_A/G_B 显式初始化时，训练开始前输出与旧骨干完全相同；新分支必须经过训练才能影响着色。只加载旧权重运行不代表已有颜色收益。

## 颜色信息来源

第一版是明确的人工颜色族，非真实颜色监督、非从 FLIR RGB 学到的统计分布：

| 类别 | 提供的范围 | 暂时限制 |
|---|---|---|
| 天空 | 蓝、浅蓝、灰蓝，允许灰云 | 不是强制每个天空像素为蓝色 |
| 植被 | 绿、黄绿、褐色 | 不能靠“植被”类别区分叶片和树干；非所有植被都应变绿 |
| 道路 | 中性灰、略暖灰 | 不把所有道路内部抹成同一颜色 |
| 人行道 | 灰、偏暖灰 | 粗粒度先验，不能保证具体材料真实颜色 |
| 人、车、建筑及其他类 | 不施加人工颜色族约束 | 全部15类 P 仍作为语义条件；不指定人物衣服、车身颜色 |

每类有3个 sRGB 样本及宽松 Lab 色度容差。约束只惩罚输出色度超出所有候选范围的距离，不匹配到单一均值、不固定亮度、不最大化饱和度。TIR 强度也不直接当 RGB 亮度。

P 的最大类别在受约束类内时，颜色强度为 `top1-top2` 乘以这些类别的概率质量；其他类不受颜色软损失约束。它只是语义分离度代理，不是 C、不保证分类正确，尤其无法排除高分错分。强度低时颜色特征与约束都会减弱。


默认输出 `runs/edge_audit/semantic_color_prior_seed42_v1/index.html`。已存在时须指定新的 `--output-dir`，不覆盖旧预览。

## 实现与三组对照

- `models/semantic_color_prior.py`：15类响应、人工颜色族、可微 Lab 转换与色度软损失。
- `models/semantic_color.py`：完整语义／颜色特征分支，原 joint512 不变，5处零初始化特征投影。
- `models/semantic_color_cycle_gan_model.py`：独立训练入口、循环路径、旧权重显式初始化和条件签名。

| `--color_condition` | 条件分支输入 | 默认色度损失权重 |
|---|---|---:|
| `none` | 分支关闭，原 joint512 保留 | 0 |
| `semantic` | 15类 P，6个颜色特征置零 | 0 |
| `semantic_color` | 15类 P＋6个软颜色特征 | 1 |

三组有相同分支定义和骨干，使用相同起点、数据、seed42、优化器和预算。`none` 控制额外训练本身的影响；`semantic` 与 `semantic_color` 检验颜色信息和颜色软约束的组合。若要单独主张损失或输入特征的贡献，还需额外对照。权重1仅为首版起点，尚未证明最优。

## Windows / Ubuntu 训练

2026-10-20 用户决定先跑“仅语义”和“语义＋人工颜色先验”两组，后续采用 tar.gz 手工上传。已提供[tar 更新包与两组顺序启动说明](语义颜色两组Ubuntu训练.md)，以其中带日期的实验名和脚本为本轮实际部署入口；下方保留通用三模式命令供单独试验。

在项目根目录、现有语义训练环境内使用同一个 Python 启动器。旧语义环境、数据和外部权重要求不变，见[Ubuntu说明](结构语义保护版Ubuntu训练.md)或[Windows说明](结构语义保护版Windows训练.md)。这些内容和 `runs/` 不随 Git 自动上传。

先检查 CUDA 环境和新CLI入口：

```bash
python scripts/run_semantic_color.py --check-only
```

下例是在**旧80轮G_A/G_B基础上**做新阶段5轮预览，学习率设为0.00002；判别器和优化器重新开始。它不是从头训练的5轮，需按相同方式运行三个模式才能判断新增条件的作用：

```bash
python scripts/run_semantic_color.py --train --name flir_v2_semcolor_from80_seed42_preview5 --init-semantic-dir runs/checkpoints/flir_v2_struct_sem512_protected_seed42_ubuntu_aligned_40_40 --stop-after-epoch 5 --lr 0.00002
python scripts/run_semantic_color.py --train --name flir_v2_semonly_from80_seed42_preview5 --color-condition semantic --init-semantic-dir runs/checkpoints/flir_v2_struct_sem512_protected_seed42_ubuntu_aligned_40_40 --stop-after-epoch 5 --lr 0.00002
python scripts/run_semantic_color.py --train --name flir_v2_none_from80_seed42_preview5 --color-condition none --init-semantic-dir runs/checkpoints/flir_v2_struct_sem512_protected_seed42_ubuntu_aligned_40_40 --stop-after-epoch 5 --lr 0.00002
```

启动器不覆盖已有实验，训练后自动导出对应新阶段epoch5的固定112张testB。`--stop-after-epoch 5`仍使用40+40学习率计划，只在整轮5结束停止。没有传 `--init-semantic-dir` 时才是从头训练；完整从头40+40的同条件对照应使用另一组新名称。

测试已有新版本权重时指定对应条件：

```bash
python scripts/run_semantic_color.py --test-only --name flir_v2_semcolor_from80_seed42_preview5 --epoch 5
```

新模式、分支宽度或颜色族不匹配会被检查点签名拒绝。旧版权重只能通过 `--init-semantic-dir` 显式初始化，不静默忽略缺少的新参数。

## 本阶段判断标准

先观察植被变天空、区域串色是否减弱，再检查脚部、轮胎等已有结构是否损伤；保留整体饱和度调整作为外观对照。对语义错分和语义正确但着色错误分开记录。定性固定同样本、同显示尺度；不把提示图变好、损失变小或通过单步检查当作正式质量收益。
