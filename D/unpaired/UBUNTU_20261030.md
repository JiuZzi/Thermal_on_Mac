## 4. RGB预热：沿用原初始化流程

新目录名避免覆盖旧实验。缓存阶段使用GPU教师，缓存完成后再训练1000步，不同时争用GPU。

```bash
python -u -m D.prepare_rgb \
  --data-manifest runs/D/ubuntu_assets_20261030/cycle_manifest.json \
  --train-limit 256 \
  --val-limit 12 \
  --device cuda:0 \
  --output-dir runs/D/rgb_selfpairs/train256_val12_ubuntu_20261030

nohup python -u -m D.train \
  --name D_rgb_softE_pilot_seed42_ubuntu_20261030 \
  --rgb-cache runs/D/rgb_selfpairs/train256_val12_ubuntu_20261030 \
  --steps 1000 \
  --save-every 250 \
  > runs/training/D_rgb_warmup_ubuntu_20261030.log 2>&1 &

tail -f runs/training/D_rgb_warmup_ubuntu_20261030.log
```

`D.prepare_rgb`的软轮廓计算与既有工具一样在CPU，`--device`用于RGB教师。日志结束出现`Saved ...step_001000`和`Next: python -m D.review`，并且`runs/D/training/D_rgb_softE_pilot_seed42_ubuntu_20261030/status.json`为`completed`后，才开始下一节。`Ctrl+C`退出`tail`只停止查看日志，不会停止nohup训练。

## 5. 正式D条件缓存

保持同一配置、同一数据清单、同一语义权重和同一GPU教师后端。先准备训练全量＋12图预览，再准备完整验证TIR；完整验证的RGB参考从原图清单读取，不另缓存无用的RGB验证P/E/Q。

```bash
python -u -m D.unpaired.prepare \
  --config D/unpaired/config.json \
  --data-manifest runs/D/ubuntu_assets_20261030/cycle_manifest.json \
  --tir-limit 0 \
  --rgb-limit 0 \
  --val-limit 12 \
  --device cuda:0 \
  --output-dir runs/D/unpaired/conditions/full_seed42_ubuntu_20261030

python -u -m D.unpaired.prepare \
  --config D/unpaired/config.json \
  --data-manifest runs/D/ubuntu_assets_20261030/cycle_manifest.json \
  --roles val \
  --domains TIR \
  --val-limit 0 \
  --device cuda:0 \
  --output-dir runs/D/unpaired/conditions/val_full_seed42_ubuntu_20261030
```

当前固定划分：训练RGB 5531、TIR 1420；完整验证TIR 690、RGB参考660。训练缓存含6951张训练图和两域各12张预览；独立验证缓存含690张TIR。P/E/Q为浮点缓存，可能占数十GB，先用`df -h /home/ubuntu/work`确认数据盘空间。

缓存中断后，原命令末尾加`--resume`；已经存在的目录不能直接重复用新缓存命令覆盖。不要一边训练一边在同一GPU上重复启动另一份缓存任务。

终端显示`TRAIN / LOSS / AUX`、ETA、显存，以及`SAVE / VALIDATE / BEST`事件。完整验证会额外生成690张图并计算指标，不是卡住；结束前不应同时再开一份训练。
